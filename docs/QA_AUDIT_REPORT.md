# سجل التدقيق الشامل (QA Audit) — أكاديمك / AcademicOS

آخر تحديث: 2026-10-18 · الفرع `claude/full-audit-academicos`

## 1. المنهج

- تشغيل التطبيق محليًا مقابل محاكيات Firebase (Auth + Firestore + Storage) **دون وضع العرض التجريبي**.
- بيانات اختبار واقعية من `scripts/seed-realistic.mjs` (حتمية ومتكررة التشغيل بلا تكرار).
- أدوار مُختبَرة: معلم (`professor`)، طالب (`student`)، مساعد تدريس، مدير قسم، مدير جامعة، دعم فني، مالية، جهة توظيف، superadmin، root_owner، وحساب جديد (تسجيل ذاتي).
- أدوات: Playwright/Chromium (سطح مكتب 1366px وجوال 390px، عربي RTL + English/Türkçe LTR)، سكربتات API مباشرة، **fuzz** لكل مسارات POST/PATCH/DELETE بأنواع بيانات خاطئة (أرقام/مصفوفات/كائنات/null/نص طويل/محارف خاصة) بأربعة أدوار، مصفوفة صلاحيات GET × 8 أدوار، اختبار تزامن (6 تسليمات متوازية، 3 تقييمات متوازية)، حمل 150 مستخدمًا متزامنًا.
- قراءة نقدية لـ `firestore.rules` و`storage.rules` (deny-all باستثناء قراءة المستخدم لوثيقته: سليمة).

## 3. العيوب التي وُجدت وأُصلحت

| # | الخطورة | الوصف | الإصلاح |

نتائج التحقق الإيجابية (بلا عيوب): حدود الأدوار على كل مسارات GET، IDOR على المشاريع/الإشعارات/المشاركات/التذاكر، التزامن (تسليم واحد من 6، تقييم واحد من 3)، تحقق توقيع webhooks (مدفوع/مكرر/ناقص/مسترد/توقيع خاطئ)، رفع الملفات (توقيع ثنائي، حجم، عدد)، تصدير DOCX/PPTX/XLSX/ZIP/MD/CSV بعد الدفع، انتهاء الجلسة → تحويل لـ `/login`، تعدد اللغات (en/tr) بلا تسرّب مفاتيح، لا overflow أفقي على 390px، لا أزرار/حقول بلا اسم، كل المسارات بلا أخطاء console.

## 4. غير مُصلَح / شروط الإطلاق (صادقة)

1. **مسار الطالب ← تكليف المقرر غير موجود في الواجهة.** الخادم والعميل (`api.submitProject`, `api.mySubmissions`) والنصوص (`pw.officialSubmit`…) موجودة، لكن لا زر "تسليم رسمي" ولا قائمة تكليفات للطالب المنضم، ولا واجهة تمرّر `courseId/assignmentId` عند إنشاء المشروع، ولا نقطة API للطالب تسرد مقرراته/تكليفاته. النتيجة: دورة "معلم ينشئ تكليفًا ← طالب يسلّم ← معلم يقيّم" تعمل عبر API فقط. إكمالها = ميزة جديدة (≈ نقطة API + اختيار تكليف في الرفع + زر تسليم) فلم تُضف بحسب قاعدة "لا ميزات جديدة".
2. **(مُحدَّث) طلب حساب معلم واعتماده من الإدارة أُنجز — انظر القسم 6.** يبقى أن ربط المستخدمين بمؤسسة (tenant) غير متاح؛ قرار المالك لاحقًا أن الطالب يختار أي تكليف دون ربط بمقرر/معلم، فلا يُبنى هذا الربط.
   (النص الأصلي للنقطة:) **لا مسار لإلحاق المستخدمين بمؤسسة (tenant).** التسجيل الذاتي يعطي `individual_<uid>` ودور طالب؛ المعلم/المؤسسة يحتاجان claims (`tenantId` + `role`) من الخارج (سكربت/SSO). بدونها لا يستطيع طالب الانضمام لمقرر معلم.
3. **الذكاء الاصطناعي غير مهيّأ محليًا** (`GEMINI_API_KEY`): الكاتب/المعلم/الحلّال/المساعد/التحقق يعودون برسائل واضحة أو هياكل بديلة؛ لم تُختبر جودة مخرجات النموذج الحقيقي. الواجهة تذكر "تهيئة مزوّد الذكاء الاصطناعي على الخادم" للطالب (لغة مشغّل).
4. **LemonSqueezy الحقيقي، PDF renderer، البريد، التحقق من الفيروسات، App Check، MFA** لم تُختبر ضد خدمات حقيقية (محاكاة محلية فقط؛ إنشاء Checkout يعطي 502 مع مفتاح وهمي بشكل مفهوم).
5. **`TRUST_PROXY`**: خلف Firebase Hosting + Cloud Run يجب ضبطه (غالبًا `2`) وإلا تتشارك كل الحركة دلو معدّل واحد (600 كتابة/دقيقة) فيرى الجميع 429 وقت الذروة.
6. **الأداء:** حزمة JS الرئيسية 1.25MB (439KB gzip)؛ `mission-control` و`brain` ثقيلان (≈80ms CPU لكل طلب؛ 150 متزامنًا ≈ 11 ثانية على عملية واحدة بمحاكي) — ضبط `min-instances`/التوسّع على Cloud Run.
7. التسليم بعد الموعد النهائي غير محجوب ولا موسوم "متأخر" (تصميم حالي).
8. مسار join بكود لمقرر مؤرشف/مسودة لا يتحقق من حالة المقرر.
9. لا ترقيم صفحات في قوائم كبيرة (طابور التسليمات حتى 3000 صف).
10. لم تُشغَّل اختبارات الواجهة اليدوية لوحدات: Writer/Tutor/Solver/Copilot/Viva مع نموذج حقيقي، ولا WhatsApp/LTI الحقيقي.

## 6. طلب حساب معلم واعتماده (الفرع `claude/teacher-approval-academicos`)

القرار: أي شخص يسجّل ويطلب «معلم»؛ يعمل حسابه كطالب إلى أن يعتمده مالك المنصة؛ الاعتماد يمنح الدور من الخادم (Firebase custom claims) بلا تعديل يدوي.

| الجزء | التفاصيل |
|---|---|
| التسجيل | `Login.tsx`: اختيار «طالب / معلم» عند إنشاء الحساب؛ للمعلم: الجامعة/المؤسسة (إلزامي) + ملاحظة اختيارية → `POST /api/teacher-requests`. الحساب طالب فورًا. بطاقة «حساب المعلم» في الإعدادات تعرض الحالة (قيد المراجعة/معتمد/مرفوض مع السبب) وتتيح التعديل/إعادة التقديم وإعادة تحميل الجلسة بعد الاعتماد. |
| الخادم | `src/server/teacher-requests.ts` (منطق نقي قابل للاختبار) + `src/server/routes/teacher-requests.ts`. مجموعة `teacherRequests` (وثيقة لكل مستخدم). |
| المراجعون | `admin` و`superadmin` و`root_owner` فقط (الطلبات تأتي من كل المستأجرين). القرار يتطلب إعادة مصادقة حديثة (`requireRecentPrivilegedAuth`) و MFA حيث يُفرض. |
| الحماية من الترقية الذاتية | الدور لا يُقرأ من أي جسم طلب؛ `PATCH /api/profile` يتجاهل `role`؛ لا أحد يقرّر في طلبه (حتى المالك: `TEACHER_SELF_DECISION_FORBIDDEN`)؛ الاعتماد لا يستبدل دورًا أعلى (مثل مدير) ويرفض بـ409؛ سقف 5 محاولات بعد الرفض. |
| الإشعار والتدقيق | إشعار داخل التطبيق + بريد عبر `sendConfiguredEmail` إن كان مهيّأً (بلغة المستخدم، 8 لغات) — فشل التسليم لا يُلغي القرار. سجل تدقيق: `teacher_request.submit/approve/reject`. |
| واجهة المراجعين | `/app/teacher-requests` (عربية RTL): تبويبات قيد المراجعة/المعتمدة/المرفوضة، اعتماد، ورفض بسبب إلزامي، شارة توثيق البريد. |
| البذر | `seed-realistic.mjs`: 6 طلبات معلقة، 3 معتمدة (لمعلمين مبذورين)، 2 مرفوضة بأسباب. |
| الاختبارات | `tests/teacher-requests.test.ts` (9 اختبارات: صلاحيات، ذاتي، رفض بسبب، عدم استبدال دور أعلى، حراسة ثابتة على `PATCH /api/profile` وعدد كتابات claims) + `scripts/test-teacher-approval.mjs` (محاكيات + خادم حقيقي: تقديم، محاولة ترقية ذاتية بـPATCH، رفض ممن لا يملك الصلاحية، اعتماد، تغيّر claims، تدقيق، إشعار، رفض وإعادة تقديم) — `npm run emulators:teacher-approval:test`. |
