# AcademicOS — دليل الإطلاق التنفيذي (Go-Live Runbook)

آخر تحديث: 2026-08-22

## الحالة الجذرية

كود المنتج **مكتمل**: جميع المسارات الوظيفية والأمنية موجودة كمسارات حقيقية، والفحوصات المستقلة عن المزوّدين تنجح (typecheck ٠ أخطاء، اختبارات core/intelligence/experience/security ناجحة، البناء ناجح، معيار الأداء محدود الذاكرة عند مليون سجل). ما تبقّى قبل الإطلاق العام **ليس نقصًا في الكود** بل **بوابات تفعيل خارجية**: بيانات اعتماد المزوّدين، بنية منشورة، واختبار بشري يدوي. هذا الملف يحوّل تلك البوابات السبع من عبارات عامة إلى خطوات تنفيذية قابلة للتنفيذ بأمر واحد أو قائمة تحقق واضحة.

القاعدة: لا تُعلَن أي بوابة "PASS" إلا بعد تنفيذها فعليًا على البيئة المنشورة (staging ثم production) — وليس على المحاكي فقط.

---

## البوابة 1 — Firebase الإنتاجي + App Check + MFA

**المطلوب:** مشروع Firebase إنتاجي، مفتاح App Check، فرض MFA للأدوار المميّزة.

1. اضبط قيم العميل والخادم من `.env.example` (Firebase client + service account + bucket).
2. سجّل أصل النشر في App Check ثم فعّل الفرض فقط بعد نجاح التسجيل:
   ```bash
   VITE_FIREBASE_APPCHECK_SITE_KEY=...
   REQUIRE_APP_CHECK=true
   ```
3. فعّل بوابة MFA وإعادة المصادقة للعمليات الحساسة:
   ```bash
   REQUIRE_ADMIN_MFA=true
   PRIVILEGED_REAUTH_MAX_AGE_SECONDS=600
   ```
4. **معيار القبول:** تسجيل دخول أدمن بدون MFA يُرفَض؛ طلب بلا App Check صالح يُرفَض؛ عملية مميّزة بعد انقضاء مدة إعادة المصادقة تُطالب بإعادة مصادقة.

## البوابة 2 — تجارب Sandbox حقيقية للدفع والاسترجاع والإلغاء

العملة الأساسية للمنتج **USD** والمزوّد يحدد حسب السوق: Stripe أو Lemon Squeezy عالميًا، مع Tap/MyFatoorah كمحوّلات إقليمية اختيارية. استخدم بيئة sandbox الخاصة بالمزوّد قبل الإنتاج.

```bash
BILLING_PROVIDER=myfatoorah
MYFATOORAH_API_BASE_URL=https://apitest.myfatoorah.com
MYFATOORAH_API_TOKEN=<sandbox token>
MYFATOORAH_PAYMENT_METHOD_ID=<sandbox method>
MYFATOORAH_WEBHOOK_SECRET=<sandbox secret>
```

خطوات الاختبار:
1. أنشئ مشروع طالب ثم نفّذ `POST /api/billing/checkout` مع `{ "planId": "project", "projectId": "..." }` → يجب أن يُعيد `PaymentURL` مستضافًا (https). الأسعار تُقرأ حصراً من `BILLING_PLANS` على الخادم.
2. أكمل الدفع في بيئة الـsandbox → يصل webhook إلى `POST /api/billing/webhook/myfatoorah`.
3. تحقق من رفض التوقيع غير الصالح (HMAC-SHA256 مقابل `MYFATOORAH_WEBHOOK_SECRET`) بـ 401.
4. اختبر الحالات: `paid` / `failed` / `pending` / `refunded` / `chargeback` وتأكد أن الصلاحية مرتبطة بالمشروع المحدد، وأن الاسترجاع أو الاعتراض المالي يسحب الباقة الصحيحة ويعيد المشروع للباقة السابقة أو المعاينة.
5. تحقق من الـidempotency: إعادة نفس `idempotencyKey` لا تُنشئ عملية مزدوجة.
6. تحقق من التسلسل: معاينة 3 صفحات مرة واحدة → محاولة ثانية 402 → دفع → مشروع كامل + Word → باقة Viva للمناقشة → استرجاع يسحب الميزة المناسبة.
7. **معيار القبول:** `GET /api/billing/status` يُظهر `configured:true` للمزوّد، و`GET /api/projects/:id/access` يعكس الباقة الصحيحة، ودورة دفع→استرجاع→إلغاء كاملة مسجّلة في السجل التدقيقي.

اختبار التدفق المحلي الكامل متوفر بالأمر `npm run emulators:student-flow:test` ويحتاج Java لتشغيل Firestore Emulator.

> Stripe و Tap مدعومان بنفس البنية إن لزم تبديل المزوّد.

## البوابة 3 — مزوّد فعلي للبريد وPush وSMS وفحص الملفات

```bash
EMAIL_PROVIDER=... EMAIL_DELIVERY_ENDPOINT=... EMAIL_API_KEY=...
PUSH_PROVIDER=...  PUSH_API_KEY=...
SMS_PROVIDER=...   SMS_API_KEY=...
VIRUS_SCAN_URL=... VIRUS_SCAN_TOKEN=... REQUIRE_VIRUS_SCAN=true
```

**معيار القبول:** إرسال بريد/إشعار/رسالة تجريبية فعلية تصل؛ رفع ملف ملوّث (EICAR) يُحجَب عند تفعيل `REQUIRE_VIRUS_SCAN`، وملف سليم يمرّ. فشل المزوّد يُرجع خطأ صريحًا لا "نجاحًا زائفًا".

## البوابة 4 — اختبار ضغط على البنية المنشورة (لا المحاكي فقط)

- شغّل `npm run test:scale` كخط أساس محلي (تم اليوم: p95 للاستعلام ~0.002ms، محدود الذاكرة عند مليون سجل).
- ثم كرّر حِمل حقيقي على النشر: طوابير الرفع/التحويل، صفوف التصحيح، مشاركة عامة، ومسارات AI تحت التزامن.
- **معيار القبول:** p95 مقبول تحت الحمل المستهدف، لا تسريب ذاكرة، ولا تجاوز لحدود المعدّل (rate limits) على المستأجر/المستخدم/المسار.

## البوابة 5 — استعادة نسخة احتياطية وكارثة تشغيلية

```bash
BACKUP_WORKER_URL=... BACKUP_WORKER_TOKEN=...
```

1. شغّل نسخة احتياطية: `POST /api/admin/backups/run`.
2. نفّذ استعادة فعلية على بيئة معزولة عبر مسارات `.../restore` (منصة/مشروع/إصدار/artifact).
3. حاكِ كارثة: فقدان منطقة/قاعدة بيانات ثم استعادة من آخر نسخة.
4. **معيار القبول:** RPO/RTO موثّقان، والبيانات المستعادة متطابقة، والاستعادة لا تكسر عزل المستأجرين.

## البوابة 6 — اختبار وصول يدوي بقارئ شاشة

فحص بشري (لا يُؤتمت). نفّذ على VoiceOver (macOS/iOS) و NVDA (Windows):

- تنقّل كامل بلوحة المفاتيح عبر المسارات الأساسية (تسجيل دخول، رفع مهمة، مساحة العمل، درع ما قبل التسليم، المشاركة).
- اتجاه RTL عربي + LTR إنجليزي؛ ترتيب القراءة منطقي.
- الإعلانات الحيّة (حالات المعالجة/النتائج) تُنطَق.
- تباين لوني ومقاسات لمس ووضع الحركة المخفّضة.
- **معيار القبول:** لا حاجز يمنع إكمال مهمة أساسية بقارئ شاشة؛ سجّل النتائج مقابل WCAG 2.2 AA.

## البوابة 7 — محولات الهوية الإقليمية الاختيارية

```bash
PACI_CLIENT_ID=... PACI_CLIENT_SECRET=...
PACI_IDENTITY_BASE_URL=... PACI_CALLBACK_SECRET=...
```

**معيار القبول:** يبقى Firebase Authentication هو المسار العالمي الافتراضي. لا يظهر أي محول هوية خاص بدولة إلا في نشر يحتاجه وبعد توفير اعتمادات وموافقات ذلك المزود؛ للمحول PACI الاختياري اختبر دورة الهوية كاملة وتوقيع الـcallback قبل تفعيله.
