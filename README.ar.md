# AcademicOS — من التكليف إلى الدليل

**AcademicOS** يحوّل التكليف الجامعي (نص، ملفات، معيار تقييم، بيانات) إلى مساحة عمل أكاديمية منظّمة:
يفهم المطلوب، ويساعد الطالب على بناء عمله بنفسه، ويتحقق من الأدلة، ويجهّزه للدفاع عنه.
الواجهة عربية أولاً (RTL) مع دعم ثماني لغات.

> النسخة الإنجليزية الكاملة: [`README.md`](README.md)

## المعمارية باختصار

- **الواجهة:** React 19 + Vite + Tailwind CSS 4، تطبيق ويب تقدّمي (PWA).
- **الخادم:** Express في `server.ts`، ومسارات مقسّمة حسب المجال تحت `src/server/routes/`.
- **البيانات:** Firebase Authentication + Firestore + Cloud Storage عبر Firebase Admin **من الخادم فقط**.
- **الذكاء الاصطناعي:** طبقة مزوّد مجرّدة، ومحوّل Gemini هو المفعّل افتراضياً.

## مبادئ التشغيل والأمان

| المبدأ | الحالة |
|---|---|
| المتصفح لا يصل إلى Firestore مباشرة | كل القراءة والكتابة عبر واجهة الخادم الموثّقة |
| كل استعلامات القوائم محدودة بحدّ صريح | لا استعلام مفتوح في `src/server/*.ts` |
| لا مستمعين لحظيين (`onSnapshot`) | التحديث عبر الطلبات والبثّ من الخادم |
| النشر على Cloud Run | يتقلّص إلى الصفر عند غياب الحركة |
| سياسة أمان المحتوى (CSP) | لا سكربتات مضمّنة في الإنتاج؛ `script-src` بلا `'unsafe-inline'` |

ملاحظة أداء غير عاجلة: تقارير التحليلات في `src/server/platform-store.ts` تقرأ حتى 5000 سجل من
`events` و`aiRuns`. إن كثر استخدامها يُفضّل استبدالها بـ `.count().get()` أو مستند ملخّص يومي.

## أبرز القدرات

- **استقبال التكليف** بنص وحتى 10 ملفات، واستخراج المتطلبات ومعيار التقييم في «حمض المشروع» (Project DNA).
- **مساحات عمل تكيفية** تظهر فيها الاستوديوهات المناسبة لكل مشروع فقط.
- **فحص التأليف والنزاهة:** يشرح الإشارات التي قد يسأل عنها المقيّم ويعطي ملاحظات تعلّم، دون إعادة كتابة النص
  ودون ادعاء كشف الذكاء الاصطناعي.
- **سجل التأليف (أدلة العملية):** خط زمني للمسودات والمراجعات وإجابات المناقشة وفحوص المصادر، قابل للطباعة
  كتقرير موقّع من الخادم (SHA-256 + HMAC) ويمكن التحقق منه في صفحة `/verify-evidence`.
- **مناقشة شفهية (Viva)** مع إدخال صوتي، ووقت ممتد، وتدفّق صديق لقارئات الشاشة.
- **ProfessorOS / CourseOS:** بناء التكليفات، ولوحة مجهولة الهوية تبيّن أين يتعثّر الفصل، وغرفة توضيح لإرسال
  توضيحات رسمية للطلاب.
- **العمل دون اتصال:** حفظ مصفوفة المتطلبات والمسودات للمشروع النشط محلياً، وطابور للتعديلات يُرسل عند عودة الاتصال.
- **تكامل LTI 1.3 / Moodle:** هيكل جاهز يحتاج إعداداً من المؤسسة (راجع مركز التكاملات).

## التشغيل محلياً

المتطلبات: Node.js 20 أو أحدث.

```bash
cp .env.example .env
npm ci
npm run dev
```

لا يوجد تجاوز للمصادقة. التحقق المحلي يتم عبر محاكيات Firebase (Auth/Firestore) برموز وصلاحيات حقيقية:

```bash
npm run emulators
npm run emulators:seed
```

## أوامر التحقق

```bash
npm run lint          # فحص الأنواع (TypeScript)
npm run lint:eslint   # ESLint مع قواعد إمكانية الوصول jsx-a11y (تحذيرات فقط)
npm test              # فحص الأنواع + كل الاختبارات
npm run build         # بناء الواجهة والخادم
npm run audit:launch  # تدقيقات الإطلاق الثابتة
```

## الإعداد للإنتاج

1. أنشئ مشروع Firebase / Google Cloud وفعّل Authentication وFirestore وCloud Storage.
2. انشر `firestore.rules` و`storage.rules` و`firestore.indexes.json`.
3. اضبط المتغيرات المطلوبة من `.env.example` في نظام الأسرار (وليس في المستودع)، ومنها
   `PROJECT_VARIATION_SECRET` و`PROCESS_EVIDENCE_SECRET`.
4. اضبط مزوّد الذكاء الاصطناعي وبيانات اعتماد Firebase Admin.
5. ابنِ التطبيق وانشره: `npm run build` ثم `npm run deploy:cloudrun`.
6. أنشئ حساب المالك الأول عبر `ROOT_OWNER_EMAIL` و`npm run bootstrap:root` من بيئة إدارية موثوقة.
7. فعّل تنبيه الميزانية في حساب الفوترة، وشغّل اختبارات شاملة على بيئة تجريبية قبل فتح الإنتاج.

تفاصيل النشر في [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)، والأمان في [`SECURITY.md`](SECURITY.md)
و[`SECURITY-TODO.md`](SECURITY-TODO.md).
